# Как работать с агентами

Инструкция по использованию AI-пайплайна в этом проекте: писать тесты через `metatrader-pom`, ревьюить через `metatrader-reviewer`, замыкать цикл через `/review-loop`.

## Предусловия

1. Установлен [Claude Code CLI](https://claude.com/claude-code).
2. CLI запущен в корне проекта: `claude` в `C:\Users\eprok\PycharmProjects\PlaywrightDemo\`.
3. При первом запуске агентов (или после правки `.claude/agents/*.md`) — **перезапусти CLI**: project-local агенты загружаются только при старте.

Проверить, что агенты видны:
```
/agents
```
Должны быть в списке: `metatrader-pom`, `metatrader-reviewer`.

---

## Три команды, которые нужны чаще всего

### 1. Написать Page Object и тесты для новой страницы

```
Используя metatrader-pom, добавь Page Object и тесты для вкладки
<Tab> акции <TICKER> (<exchange>) по образцу NVDA.
```

Пример:
```
Используя metatrader-pom, добавь Page Object и тесты для вкладки
Dividends акции TSLA (nasdaq) по образцу NVDA.
```

Что произойдёт:
1. Агент прочитает эталоны (`pages/nvda/*`, `tests/nvda/*`).
2. Создаст `pages/tsla/` и `tests/tsla/`.
3. Прогонит `pytest tests/tsla/ -v` и починит до зелёного.
4. Отчитается списком созданных файлов и summary pytest.

### 2. Проверить код по правилам

```
Запусти metatrader-reviewer на pages/<ticker>/* и tests/<ticker>/*.
```

Пример:
```
Запусти metatrader-reviewer на pages/tsla/* и tests/tsla/*.
```

Что получишь:

| поле | значение |
|---|---|
| таблица находок | `path:line / severity / правило / описание / рекомендация` |
| severity | `blocker` / `major` / `minor` / `nit` |
| вердикт | `approve` / `request changes` / `reject` |

Reviewer **не правит код**, только показывает нарушения. Исправления — через writer-а.

### 3. Автоцикл до чистого approve

```
/review-loop pages/<ticker>/ tests/<ticker>/
```

Пример:
```
/review-loop pages/tsla/ tests/tsla/
```

Что произойдёт:
```
reviewer → если approve, стоп ✅
       → если request changes:
             writer правит
             pytest прогоняется
             если упал — стоп ❌
             если зелёный — reviewer снова
       → max 3 итерации, потом стоп
```

## Полный сценарий: покрыть новый тикер с нуля

```
# 1. Запустить write
Используя metatrader-pom, добавь Page Object и тесты для вкладки
Overview акции META (nasdaq) по образцу NVDA.

# 2. Прогнать автоцикл ревью
/review-loop pages/meta/ tests/meta/

# 3. Посмотреть allure (локально)
allure serve reports/allure_report
```

## Когда какой инструмент использовать

| Задача | Инструмент |
|---|---|
| Новый тикер / новая вкладка metatrader.com | `metatrader-pom` |
| Правка существующего POM-файла metatrader | `metatrader-pom` |
| Проверить, что я написал руками, соответствует правилам | `metatrader-reviewer` |
| Полный цикл «написать + довести до approve» | `metatrader-pom` + `/review-loop` |
| Общий поиск по кодовой базе («где определено…») | `Explore` (встроенный) |
| Планирование крупного рефакторинга | `Plan` (встроенный) |
| Создать нового агента | `prompt-engineer` (встроенный) |
| Playwright-код для другого сайта | `playwright-pom-automator` (user-level) |

## Правила, которым подчиняется агент

Все правила — в [`CLAUDE.md`](./CLAUDE.md). Файл автоматически попадает в контекст каждого субагента, запускаемого в этом проекте. Если нужно изменить правила — правь только его, агенты не трогай.

Структура `CLAUDE.md`:
- **10 правил** написания тестов (адаптировано из Playwright best practices).
- **9 жёстких правил проекта** — специфика POM этого репо (`_expect_*`, `_pages[request.node.nodeid]`, запретный список файлов).
- **Чеклист готовности задачи** — писатель сверяется перед отдачей.

---

## Что НЕ будет трогать агент

Запрещены к правке (прописано в `CLAUDE.md`):
- `pages/base_page.py`
- `pages/nvda/**`, `pages/search/**`, `tests/nvda/**`
- `pytest.ini`, `requirements.txt`, корневой `conftest.py`
- `screenshot_store.py`

Если агент видит, что находка требует правки в этих файлах — он помечает её `wontfix / grandfathered` и обосновывает.

## Создать своего агента

Через встроенный `prompt-engineer`:

```
Используй prompt-engineer. Напиши промпт для нового агента <имя>
под задачу <что делает>. Контекст проекта: <стек, конвенции>.
Положи в .claude/agents/<имя>.md.
```

После создания — **перезапусти CLI**, иначе агент не подхватится.

Структура файла:
```markdown
---
name: имя-через-дефис
description: короткое описание + 2-3 <example> блока
model: sonnet | opus | haiku
color: любой
---

Ты — <роль>.

# Источник правил
Корневой `CLAUDE.md`. При конфликте — приоритет у него.

# Процесс
1. ...
2. ...

# Формат ответа
...

# Чего НЕ делать
- ...
```

## Траблшутинг

| Симптом | Причина | Фикс |
|---|---|---|
| `Agent type 'metatrader-pom' not found` | Project-local агент не загружен в текущую сессию | Перезапусти `claude` CLI |
| Агент пишет код «вообще» вместо стиля проекта | Он не прочитал `CLAUDE.md` или эталоны | В промте явно: «прочитай pages/nvda/* перед работой» |
| Reviewer повторяет находку, которая grandfathered | Нет контекста прошлой итерации | В промте: «finding X — wontfix, не повторяй» |
| `/review-loop` крутится без прогресса | Writer не может исправить без нарушения правил | Проверь логи — обычно он сам останавливается на `reject` или skipped |
| Pytest упал после правок writer-а | Писатель сломал тесты, пытаясь угодить reviewer-у | Откати последний виток, усили промпт: «не ломать существующие ассерты» |

---

## Как работать правильно

1. **Не правь код агентами молча** — читай отчёт, принимай решение, что оставить.
2. **Если агент предлагает странное** — не борись с ним, посмотри в `CLAUDE.md`: правило либо отсутствует, либо нечёткое. Правь правило, а не промпт.
3. **Reviewer не всегда прав** — это предложения, не вето. Grandfathered-находки нормальны.
4. **Прогоняй `/review-loop` перед коммитом** — дешёвый гейт качества.
