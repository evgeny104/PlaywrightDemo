# /review-loop — автоматический цикл writer↔reviewer

Запусти пайплайн ревью с автоматической доработкой кода до вердикта `approve` или до исчерпания лимита итераций.

## Аргументы

`$ARGUMENTS` — список путей к файлам или папкам для ревью (пробелы — разделитель).
Если аргументов нет — взять изменённые файлы из `git diff --name-only` (без staged).

## Константы

- `MAX_ITERATIONS = 3`
- Эталоны (НЕ ревьюишь, НЕ правишь): `pages/base_page.py`, `pages/nvda/**`, `pages/search/**`, `tests/nvda/**`.
- Правила ревью: `CLAUDE.md` (загружается автоматически).

## Процедура

Для каждой итерации `i = 1..MAX_ITERATIONS`:

### Шаг 1 — Reviewer

Запусти subagent `metatrader-reviewer` на указанных файлах. В промте передай:
- список файлов,
- номер итерации,
- (если i > 1) краткую сводку, что писатель отрапортовал в прошлый ход (fixed / skipped с причинами) — чтобы reviewer не повторял grandfathered-находки.

Reviewer вернёт отчёт по формату с одним из вердиктов: `approve` / `request changes` / `reject`.

### Шаг 2 — Проверка вердикта

- **`approve`** → распечатай итоговый лог цикла и остановись. Цикл завершён успешно.
- **`reject`** → остановись, выведи причину. НЕ продолжай цикл: это сигнал о фундаментальной проблеме, нужен человек.
- **`request changes`** → перейди к шагу 3.

### Шаг 3 — Writer

Запусти subagent `metatrader-pom` (или `playwright-pom-automator` как fallback — он читает тот же `CLAUDE.md`) с задачей исправить находки. В промте передай:
- таблицу находок от reviewer-а целиком,
- явное указание: если какую-то находку исправить нельзя без нарушения другого правила — пометить `skipped` с обоснованием, а не делать workaround,
- требование: прогнать `pytest <пути из $ARGUMENTS>` после правок и приложить summary line.

### Шаг 4 — Проверка pytest

Если writer сообщил, что pytest упал — остановись, выведи текст падения. НЕ продолжай цикл: правки сломали тесты, нужен человек.

Если pytest зелёный — вернись к шагу 1 для следующей итерации.

### Выход по лимиту

Если `i == MAX_ITERATIONS` и вердикт всё ещё `request changes`:
- Останови цикл.
- Выведи остаток находок.
- Явно отметь: «Цикл не сошёлся за N итераций — требуется ручной разбор».

## Формат итогового отчёта

Итоговое сообщение пользователю (одно, после остановки цикла):

```
=== /review-loop итог ===
Статус: approved / stopped (pytest failed) / stopped (max iters) / stopped (rejected)
Итераций: N
Проверенные файлы:
  - path 1
  - path 2
История:
  iter 1: reviewer → M находок; writer → X fixed / Y skipped (пример: #2 wontfix grandfathered)
  iter 2: reviewer → K находок; writer → ...
  iter 3: reviewer → approve
Pytest финальный: 6 passed in 15.21s
```

## Что не делать

- Не фиксить код сам в main-сессии — только через subagent'ов (это важно для демо и прозрачности).
- Не трогать запретный список путей.
- Не крутить цикл больше `MAX_ITERATIONS`.
- Не продолжать цикл после `reject` или падения pytest.
